# BT1: prospective binding transport screen

Hypothesis: IM1 content interaction terms can be reused across new entity names by replacing only the anchor image. This is a mechanism screen, not a novel architecture claim or full DoD success. Binding vectors and cross-context KV offsets are prior art.

Frozen Qwen2.5-3B, existing sealed IM1 bank, no gradients. Target role pairs X/Y, C/D, K/M fixed before results. Four balanced non-anchor worlds (blue,green,A), (blue,green,B), (yellow,blue,A), (yellow,blue,B). Four direct/reference questions, 48 cases per mode. Names are untested in IM1, not asserted unknown to pretrained model.

Modes: anchor-only negative control; unchanged donor order2 (wrong-name control); target anchor + donor singleton terms; target anchor + donor pair terms; exact target prefix reference. Target calibration uses only red/red/first-selected anchor, one prefill per role pair. No target non-anchor image before all candidate outputs sealed. Runtime candidate assembly sees numeric world, no gold or question. FP64 sum then BF16 cast. Fixed token lengths and exact split boundaries required, otherwise reject without choosing replacement names. Exact cached/full generation check on each target anchor. Greedy existing 6-token limit, EOS required, strict color word with optional punctuation.

Gate for either rebased mode: 48/48 factual questions correct, and no reference-correct/candidate-wrong case; anchor control must score below candidate. Pair-order gain reported separately. No statistical independence claim, no speed superiority claim. This is deliberately a small disqualifying screen; passing would require new values, larger entity pools, paraphrases and scale tests.

Prior art: https://arxiv.org/abs/2310.17191 ; https://arxiv.org/abs/2409.05448 ; https://arxiv.org/abs/2510.12872 . Abstract-level grounding: binding representations / ordering subspaces / anchored cross-context KV offset correction. No novelty clearance.
